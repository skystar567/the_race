# 任务 07：学习路线验收计划

**状态：C 代码审核未通过，任务 07 未接入主线。以下都是待验证案例。** 改编自成员 C 的 [路线材料](https://github.com/skystar567/the_race/blob/2924f0961e94d8a22bbdafc554d601df1665d83c/docs/member-c/route-cases.md)，以主线领域结构为准，不承诺旧接口及返回字段。

## 判断规则

- 只有 `precedes` 决定学习先后；`contains` 与 `contrasts` 不参与排序。关系的 `origin` 保留 `source` 或 `suggested`；`suggested` 不能显示成原文已经确认的结论。
- 知识点 `status=needs_review`、其 `conflicts`、缺失页面/端点及循环必须影响路线可信程度。不能因为所有边都为 `source` 就忽略节点待核对状态。
- 当前学习位置只表示用户指定的起点，不表示掌握度。只有它位于目标的前置链上时，才可略去它及相关前置部分；无关起点不得裁掉共同前置。
- 固定知识版本，同层按稳定 ID 排序。出现不确定部分只能展示可确定部分，待核对候选可单列，不宣称完整无误。
- 以下 `complete/partial/blocked` 描述预期语义，最终字段需适配主线。案例不允许用模型补边绕过缺口。

## 案例

未特别说明时，节点有页面且已确认，箭头均为 `precedes`、`origin=source`；K2 的稳定 ID 小于 K3。

| 编号 | 输入 | 预期行为 |
| --- | --- | --- |
| R1 链式 | K1→K2→K3，目标 K3 | 完整顺序 [K1,K2,K3] |
| R2 分支 | K1→K2/K3，K2/K3→K4 | K1 首、K4 尾，同层 K2 在 K3 前 |
| R3 循环 | K1→K2→K3→K1，目标 K3 | 标出循环并阻断完整路线，不伪造拓扑序 |
| R4 缺口 | K9→K3→K4，K9 不存在 | 标记 K9 缺失；K3/K4 只可作为不完整候选，不称完整路线 |
| R5 混合关系 | `contains`、`contrasts`、`precedes` 混合 | 只有 `precedes` 决定先后，其余不隐式转为前置 |
| R6 建议关系 | K1→K2 为 `source`，K2→K3 为 `suggested` | 保留来源差异与待核对提示，不能输出无警告的确定完整路线 |
| R7 有关起点 | K1→K2→K3→K4，current=K2，目标 K4 | 可把 K1/K2 列为此前部分，后续 [K3,K4]，不称“已掌握” |
| R8 循环与分支 | K1/K2/K3 构成环，K5→K4→K3，目标 K3 | 可展示确定部分 [K5,K4]，同时标出环和无法到达确定目标的限制 |
| R9 无关起点共享前置 | A→T、A→U，目标 T，current=U | 告知 U 不在目标前置链；保留完整候选 [A,T]，不得把 A 放进此前部分后仅返回 [T] |
| R10 待核对节点 | A→T 为 `source`，A.status=`needs_review`，两者均有页面 | 显示 A 待核对及其冲突依据；不得返回无警告 `complete`；待核对节点不能混入确定路线 |

R9、R10 来自本轮可复现缺陷，必须补为回归检查。每个案例都需确认后端结果和界面提示一致。
