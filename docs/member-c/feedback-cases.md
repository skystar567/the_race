# 任务 12：问题反馈与纠错验收计划

**状态：C 代码审核未通过，任务 12 未接入主线。** 材料改编自成员 C 的 [反馈案例](https://github.com/skystar567/the_race/blob/2924f0961e94d8a22bbdafc554d601df1665d83c/docs/member-c/feedback-cases.md)。旧实现重跑章节时未将反馈正文交给模型，却在任务完成时标为 `resolved`，不能作为有效纠错证据。

## 流程约束

1. 从知识点、知识点页面或关系记录目标、反馈正文及其知识版本，验证课程归属与目标存在性。
2. **反馈正文必须进入受控回查**，连同目标和相关原文引用提供给整理任务。正文作为待核实的用户说明，不能替代资料或成为系统指令。不能仅重跑第一条引用所在章节。
3. 回查允许重读已整理的相关范围；使用主线公开任务接口，不能把正常增量整理的“没有新片段”当成反馈完成。关系反馈须核对两端、关系类型和相关依据。
4. 候选内容通过校验后再发布；失败保留当前知识版本，旧版本和个人笔记保持可追溯。
5. 持久保存反馈结论及其证据，异步任务完成、失败或重启后，反馈状态与界面都应更新。

## 分开表达执行结果与纠错结论

| 层次 | 应表达的内容 | 不能据此推断 |
| --- | --- | --- |
| 整理任务 | 排队、执行中、完成、失败 | `completed` 不等于问题已解决 |
| 反馈处理 | 待处理、回查中、已核实解决、仍需处理 | 页面发生变化不等于纠错正确 |
| 核对结论 | 已纠正并有依据、原内容有依据、资料不足、仍有冲突、执行失败 | `unchanged` 不自动等于已解决；`changed` 不自动等于已纠正 |

具体枚举由实现确定。只有结论与证据足以回答用户提出的问题时才能标为已解决；资料不足、冲突仍在或执行失败不能显示“已修正”。如核实原内容正确，应明确说明与引用，不能只写无变化。

## 待执行案例

| 编号 | 输入/条件 | 验收点 |

| F2 资料不足 | 正文要求教材未提供的结论 | 不补造资料，保持需处理或资料不足，不能标已修正 |

| F4 内容无变化 | 任务完成但目标定义和页面不变 | 依据决定“原内容正确”还是“仍未解决”；不能自动 `resolved/unchanged` |
| F5 文案变化 | 模型只换措辞，原错误未纠正 | 不因字符串不同判成已纠正 |
| F6 异步执行/重启 | 队列已有其他任务，反馈任务后执行 | 跟踪正确任务；轮询/恢复后结束回查状态，不永久停在 checking |

| F8 关系/页面目标 | 关系错误或页面特定段落错误 | 目标验证有效，回查实际目标及相关引用，不能只比较某个端点定义 |

| F10 课程与笔记隔离 | 其他课程目标、用户编辑笔记 | 拒绝越课程目标，纠错前后用户正文/拓展标记保持完整 |
