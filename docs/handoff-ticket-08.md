# 任务 08：追加整理与版本发布交接

> 后续更新：08 已合入 main。09／10 已实现冲突记录与恢复次数，当前扩展字段见[09／10 交接](handoff-ticket-09-10.md)；本文的追加与版本读取契约继续有效。

任务分支 `ticket/08-incremental-knowledge-update`，基于已合入 main 的任务 03（`e592041`）。实际检查和真实样本见[验证记录](verification-ticket-08.md)。任务 02、03 文档中的“仅首次整理”限制由本文替代，原有读取路径保持兼容。

## 学生操作

在「资料阅读」导入新 Markdown，进入「知识图谱 → 选择追加整理范围」，选择尚未整理的资料或章节，再点击「追加整理」。整理期间可以继续打开旧图谱、知识点及原文；成功后显示新增、补充和待核对数量。失败保留已发布知识并显示原因。没有模型凭据时仍可阅读。

首次整理和追加整理共用范围选择器。已整理的范围禁用；部分整理的资料或父章节仍可选择，后端只取其中未整理的片段。范围外资料保持未整理。「刷新知识」同步取得当前知识和范围，支持另一个窗口导入资料后刷新。

## 兼容的 HTTP 契约

| 操作 | 方法与路径 | 更新后的约定 |
| --- | --- | --- |
| 发起整理 | `POST /api/courses/{course_id}/tasks` | 请求仍为 `material_ids`、`chapter_ids`，成功 202；自动区分首次或追加 |
| 任务进度 | `GET /api/courses/{course_id}/tasks/{task_id}` | 新增 `parent_version_id`，首次为 null，追加固定为创建时的版本 |
| 重试失败任务 | `POST /api/courses/{course_id}/tasks/{task_id}/retry` | 基准未变化才复用成功步骤；已有活动任务或版本变化返回 409 |
| 知识快照 | `GET /api/courses/{course_id}/knowledge?version_id=...` | 省略参数读当前；指定参数读不可变旧版本；已发布响应新增 `parent_version_id` |
| 整理覆盖 | `GET /api/courses/{course_id}/knowledge/coverage?version_id=...` | 按指定版本中的累计片段判断；已导入不代表已整理 |
| 版本列表 | `GET /api/courses/{course_id}/knowledge/versions` | 保留旧版本及父版本关系 |

知识点和来源路径保持 `knowledge/versions/{version_id}/concepts/{concept_id}`、`knowledge/versions/{version_id}/sources/{snippet_id}`。必须把同一个 `version_id` 传给图谱、详情和引用。其他课程的资料、章节、版本或来源仍拒绝读取。

创建任务时，空范围、范围全部已整理、存在同课程活动任务、未整理部分超过 60,000 字符均返回 422；没有截断资料。60,000 字符限制针对本次新片段，不是累计知识库大小。

本轮真实追加的结果字段如下（省略其余快照内容）：

```json
{
  "version_id": "9fc1314d-4e6f-4584-98e9-270b6f683ccb",
  "parent_version_id": "11ca2523-1405-425c-951c-345e961a6c4e",
  "summary": {
    "new_concepts": 2,
    "updated_concepts": 2,
    "conflicts": 0,
    "needs_review": 0
  }
}
```

知识点新增可选字段 `is_updated`、`identity_reason`；`status` 使用 `confirmed` 或 `needs_review`。`is_new`、`is_updated` 表示本次版本变化，`summary.needs_review` 是当前版本全部待核对知识点的数量。首次构建的旧快照可以没有这些新增字段。`conflicts: 0` 是本阶段兼容字段，不表示已实现冲突检测。

## 身份与发布规则

- 抽取仅接收新范围。整合接收旧知识目录、旧新原文与新片段标识；只输出新增或需要补充的候选。模型仍统一使用 `deepseek-flash`。
- 沿用旧知识点必须显式返回本课程基准版本内的 `existing_id`、确认状态和判断说明，同时引用该知识点的旧依据与本次新依据。名称相同不会触发程序自动合并；无法确认的候选独立保留并显示待核对说明。
- 程序保留未受影响的页面、旧别名、旧出处和旧章节归属。名称变化不改变已确认的知识点 ID；新知识点 ID 按课程、任务与局部 key 生成。新关系按实际端点 ID 生成，已有关系保留 ID，允许不同任务重复使用模型局部 key。
- 所有模型引用在与旧引用合并前校验，不能用旧引用覆盖掉无效新输出。候选须通过来源、章节、关系端点及页面引用校验；模型不能直接改数据库或原文件。
- 创建任务时固定父版本，发布事务比较当前指针与父版本。仅相等时写入完整快照、标记发布并切换指针；版本变化时拒绝过期候选。重复发布同一任务返回原版本，不能把当前指针倒退。
- 浏览器取得完整新快照与同版本覆盖信息后统一切换；取消旧详情、来源请求，并检查返回版本。旧版本及其来源一直可通过固定版本路径读取。

语义判断仍依赖模型及人工验收，结构校验不能证明所有概念等同或保证全部旧内容被语义保留。任务 09 继续实现易混概念和跨来源冲突展示；任务 10 完整验收故障恢复；任务 11 验证更新时的问答与个人笔记。

## 升级和协作

启动 API 或 worker 时自动为已有 `task` 表增加可空的 `parent_version_id`，迁移使用写事务串行执行；不清库、不改原文。已有首次任务的父版本为 null，原有已发布知识可直接读。本轮已从任务 03 的真实旧数据库副本升级并追加成功。

B 的问答、笔记和 C 的路线继续使用版本固定的读取接口。不要按名称或别名保存跨版本引用，也不要改写知识模块的表。任务 08 合入后，A 可以进入 09、10；B 的 11 还需要 05 完成。

当前整合和页面生成会读取累计原文，小样本已验证，大型课程的模型上下文容量尚未验收；程序不会静默裁掉旧证据。需要大范围演示时由任务 14 检查并调整处理策略。
