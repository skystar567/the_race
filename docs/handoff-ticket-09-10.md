## 概念身份和资料冲突

学生继续使用「导入 Markdown → 选择追加整理范围 → 追加整理」。模型比较定义、上下文和出处：同义名称沿用知识点 ID，同名异义独立保留；同一概念在不同适用条件下可以并存，不机械标为冲突。不确定的概念仍显示「待核对」。

真正相互排斥的主张保存在知识点的可选 `conflicts` 数组中，图谱和列表显示「有冲突」，页面按双方表述、适用语境及引用展示，点击可打开当前版本中的对应原文。冲突与待核对可以同时存在。旧快照没有 `conflicts` 时按空数组处理。

```json
{
  "conflicts": [{
    "id": "程序生成的稳定冲突标识",
    "reason": "双方对于同一条件给出相互排斥的规定",
    "claims": [
      {"statement": "第一方主张", "context": "第一方适用语境", "citation": {"snippet_id": "旧片段ID", "quote": "旧原文引文"}},
      {"statement": "第二方主张", "context": "第二方适用语境", "citation": {"snippet_id": "新片段ID", "quote": "新原文引文"}}
    ]
  }]
}
```

这是结构示意，不是真实资料内容。真实结果和来源见验收记录。HTTP 路由沿用 [08 交接](handoff-ticket-08.md)，不新增独立冲突接口。`summary.conflicts` 现在统计当前版本实际保留的冲突总数，而非只统计本次新增；`needs_review` 同样是当前总数。

发布规则：

- 每处冲突至少有两个不同原文片段，各方引用须属于该知识点并通过原文校验；表述、理由和适用语境不能为空。
- 新冲突必须包含本次新依据；补充已有概念时还须包含其旧依据。冲突不允许绕过原有引用、章节、关系和页面校验。
- 程序保留旧冲突和旧证据。相同概念、相同引文双方即使换序或改写说明，也保留旧冲突 ID 与记录，避免反复追加导致重复计数。
- 稳定知识点 ID、旧关系身份、原文及历史快照继续保留。展示分歧不表示系统已经解决或裁定冲突；本任务没有增加手动裁决入口。

语义是否等同、主张是否矛盾由模型结合资料判断，程序校验不能证明任意文本的语义正确。问答、路线和导出应保留待核对及冲突标记，不能把有冲突的内容当成唯一确定结论。

## 持久任务与恢复

任务读取新增 `recovery_count: number`，表示任务处于运行状态但原 worker 中断后，被重新接管的次数。首次领取和用户主动重试不增加该数；旧任务默认 0。界面分别显示恢复后的等待、执行、完成或失败状态。

默认启动方式不变，应用启动独立 worker。SQLite 全局租约使同一数据目录中一次只执行一个整理任务；其他课程的任务可排队查询。同课程仍拒绝重复活动任务。

worker 意外中断后，重启应用或 worker，等原租约到期即可自动接管，复用持久保存的成功步骤。默认租约 45 秒，默认心跳 10 秒；等待还受 worker 轮询影响，不保证精确恢复时刻。慢模型调用期间续租；丢失租约的旧进程不能保存步骤或切换发布指针。

```sh
# 独立启动 worker，通常由原有启动脚本自动完成
.venv/bin/python -m campus.worker --data-dir data
```

CLI 可选 `--lease-seconds`，要求有限数值且至少 2 秒，心跳自动缩短到不超过期限的三分之一。生产演示建议保留默认值；验收用 2 秒缩短故障等待。

暂时网络错误、HTTP 408／429／5xx 最多调用 3 次；400／401／403 等请求和凭据错误明确失败。空输出、截断、解析或业务校验失败不作为成功步骤缓存。失败任务仍通过原有重试接口恢复；基准版本已改变则拒绝复用旧结果，需重新发起整理。

模型已经计算但结果尚未保存时，恢复可以重新调用模型，不承诺外部调用恰好一次。同一任务的发布继续幂等；恢复不会多发布一个版本。首次失败不显示可用知识，增量失败和恢复期间旧知识仍可读取。
