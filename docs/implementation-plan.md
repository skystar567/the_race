# 校园课程学习助手：开发任务清单 v0.1

状态：依据已确认的 [产品方案](product-plan.md) 和 [技术方案](technical-design.md) 拆分。独立任务 01 已完成，详见[验证记录](verification-ticket-01.md)；整体 M1 尚未完成。勾选表示实际完成且满足相应检查，不表示用户已经确认过方案。后续执行以[15 项独立任务](../.scratch/course-learning-assistant/tickets-index.md)为准。

## 执行约束

- 技术栈：React、TypeScript、Vite、Cytoscape.js、Python、FastAPI、SQLite。
- 所有真实模型调用统一使用 `deepseek-flash`；抽取和整合开启思考，交互问答默认关闭思考。其他模型任务同样使用 Flash。
- 本机单人、多课程，无登录注册；模型调用凭据留在后端。
- 六个业务模块：资料、知识、整理任务、学习、个人笔记、导出。调用方通过模块接口协作，不直接修改其他模块拥有的数据。
- 原始资料保留，知识按版本发布，个人笔记单独维护；旧引用必须能够继续核查。
- 先形成真实资料驱动的完整操作，再扩展范围。测试用可控模型响应与真实生成结果分别标识，不能把测试响应当作真实模型演示。

## 里程碑与依赖

| 里程碑 | 前置条件 | 完成时可展示的结果 |
| --- | --- | --- |
| M1：真实资料到图谱 | 开始实现，完成运行环境与模型接入准备 | 一小节真实教材生成图谱，点击知识点能查看内容和原文 |
| M2：学习使用 | M1 有可读取的知识版本与有效引用 | 带依据问答、可编辑笔记及学习路线 |
| M3：持续更新与恢复 | M1 的任务和版本基础、M2 的学习成果 | 新资料更新知识，任务失败可恢复，旧笔记及引用保留 |
| M4：演示交付 | M1—M3 达到各自完成标准 | 完整资料包、可复现的预构建与增量演示、本机启动说明 |

## M1：真实资料到图谱

- [ ] **M1.1 项目基础**：建立前后端项目与六个模块的职责位置，确认依赖兼容性并锁定可用版本，准备独立本地数据目录和配置说明。检查前端构建与类型检查能够分别执行，后端能在本机启动。
- [x] **M1.2 真实材料样本**：从《计算机操作系统（第四版）》已确定的演示范围选取一小节作为首个验证样本，保留教材名称及原始出处；原始教材不被清理或覆盖。
- [ ] **M1.3 资料导入与定位**：保留导入原文，识别章节编号及整理范围，为原文片段分配稳定标识。标题规范化或清理展示必须保留到原文的映射；识别缺失图片并明确显示。
- [ ] **M1.4 持久化基础**：建立课程、资料与片段、知识点身份、知识版本、版本内关系与页面、任务和步骤结果的持久结构。知识名称与别名可变化，身份不随之重新分配；候选版本与已发布版本分开。
- [ ] **M1.5 Flash 适配器**：通过 `/responses` 验证真实 Flash 调用，抽取采用 JSON Schema，验证流式事件和完成状态的处理。检查空输出、截断、错误状态及片段标识；接口兼容或格式合法不能替代内容验收。
- [ ] **M1.6 首次整理流程**：贯通章节识别、知识抽取、概念整合、知识页面生成、校验与首次发布。工作进程保存阶段结果；无效来源、关系端点或输出结构不能发布为可用知识。
- [ ] **M1.7 最小图谱界面**：完成课程选择、资料导入及整理状态、章节概览、知识点展开、详情与原文定位。保留图谱浏览位置，展示三种关系及其来源或推断属性，支持文字、公式和代码阅读。

完成标准：从真实 Markdown 到图谱和可追溯知识页面的完整操作可运行；数据能够重新打开，未整理范围不被显示为已完成。依赖安装成功或静态图谱展示本身不足以完成 M1。

## M2：学习使用

- [ ] **M2.1 检索与范围**：实现课程、资料和章节范围限制；结合概念目录、别名、中文关键词及关联知识检索，并回查原文。覆盖“进程”“线程”等短词；含糊问题可由 Flash 从允许的目录选择知识点。暂不引入向量检索，记录需要补充召回的真实失败案例。
- [ ] **M2.2 带依据问答**：一次回答绑定一个知识版本与明确范围，流式展示与最终完成状态区分。最终引用需属于允许的原文片段；资料不足、生成中断与完成回答分别表示，不能把未通过引用校验的内容当作已完成答案。
- [ ] **M2.3 拓展解释**：仅在学生主动选择后调用资料外补充解释，保留明确标记；不自动写入课程知识库。保存为笔记后继续保留标记。
- [ ] **M2.4 个人笔记**：从所选知识点、解释或问答生成 Markdown 笔记，保留知识版本与原文引用。支持编辑和保存，不依赖重新生成知识页面保存个人修改。
- [ ] **M2.5 学习路线**：围绕目标收集所需前置知识并排序，模型解释安排理由。包含和对比关系不参与前置排序；循环、缺口和待核对关系明确显示，路线在图谱中突出显示。
- [ ] **M2.6 学习交互**：完成章节与资料筛选、知识焦点、问答、笔记和路线的连贯交互。切换课程时同步问答范围，检查跨章节关联和全图入口。

完成标准：能够使用真实课程知识完成有来源的提问、保存个人笔记、获取有依据或标识清楚的学习路线。既检查引用存在，也核对引用确实支持选定样例中的关键结论。

## M3：持续更新与恢复

- [ ] **M3.1 增量整合**：追加 Markdown 后识别已有概念与新概念，维持稳定知识点标识，更新相关页面和来源。对不同名字的同一概念、相同名字的不同概念分别验证；无法判断的候选保留并标记待核对。
- [ ] **M3.2 冲突保留**：对明确存在差异的资料表述保留出处和适用语境，不静默覆盖。记录问题而不把所有措辞差异都判为事实冲突。
- [ ] **M3.3 一致发布**：校验候选版本后切换当前知识版本，图谱、详情、引用与一次问答读取约定版本。更新过程保持旧版本可用，失败不能使不完整知识成为当前版本；发布后展示新增、补充和冲突内容。
- [ ] **M3.4 任务恢复**：持久保存任务状态及已成功步骤的结果，一次执行一个整理任务。验证工作进程中断、外部调用失败、响应截断和重试，复用已保存结果；外部请求可能重复执行，但不能重复发布知识。
- [ ] **M3.5 问题反馈**：允许学生针对知识点或关系描述问题，回查原文并重新整理相关范围。反馈不是新的教材事实；处理完成但问题未解决时，不声称已经修正。
- [ ] **M3.6 历史引用与笔记**：更新后旧回答与笔记仍可定位当时原文，个人正文不被覆盖；相关依据变化时给出检查提示。验证同时保存笔记与整理发布时两者互不覆盖。

完成标准：现场添加短资料能真实改变课程知识；中断或错误不会损坏已有知识及个人成果；恢复后可以继续生成完整、可追溯的新版本。

## M4：演示交付

- [ ] **M4.1 完整导出**：导出知识页面、关系索引、个人笔记和已导入原始 Markdown。固定导出所采用的知识版本，收齐历史笔记引用需要的原文依据，验证页面链接、来源引用及拓展标记；不承诺恢复原本缺失的图片。
- [ ] **M4.2 真实演示样本**：以第 2 章和 3.5—3.8 节为演示总体范围，留出一小段作为现场增量材料。预构建由真实处理流程产生并可重新构建；增量摘录标明真实来源。
- [ ] **M4.3 代表问题验收**：完成约 20 个教材问题的要点与来源标注，运行真实 Flash 验证。检查概念解释、同义或模糊表达、跨知识点问题和资料不足，不用逐字相同判断模型正确性。
- [ ] **M4.4 稳定约束验证**：自动检查课程范围、引用合法性、版本读取、知识点身份、路线循环、失败不发布、恢复后不重复发布、笔记保留与导出完整性。模型异常使用可控响应复现，避免靠偶然真实接口故障验证恢复能力。
- [ ] **M4.5 本机交付**：提供首次准备说明和一条启动命令，启动后端及工作进程，浏览器通过一个本机地址访问。检查数据保留、进程重启和前端构建产物加载；运行时模型调用仍需要联网。
- [ ] **M4.6 演示操作说明**：按产品方案完成图谱、问答、笔记、路线、现场增量和导出操作说明，并列明目前材料缺图、未覆盖章节及实际验证结果。记录真实观察到的耗时，不承诺未测得的速度或准确率。

完成标准：在目标演示电脑上按说明运行，能够完成产品方案约定的主流程与关键异常检查，导出资料包可在应用之外阅读。

## 验证如何分配到里程碑

| 验证类型 | 最早开始 | 最终完成 |
| --- | --- | --- |
| 原文定位、结构化抽取及首次发布 | M1 | M1，再随相关变更回归 |
| 问答、检索、笔记与路线样例 | M2 | M4 的代表问题验收 |
| 增量、版本一致性、失败恢复 | M3 | M3，再在交付环境检查 |
| 导出、本机启动和完整演示 | M4 | M4 |

测试围绕模块对外接口和用户可观察结果展开。实现阶段根据新增功能、失败或未解决问题补充验证，不反复运行无关检查来替代完成任务。
