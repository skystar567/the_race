# 校园课程学习助手 Demo 开发规格

Status: ready-for-agent

## Problem Statement

大学生课后需要同时阅读教材、课堂资料和补充文档。同一知识点可能散落在多个章节，知识之间的前置关系和适合对比的内容不容易发现；查找解释、核对出处、整理笔记和决定下一步学什么，需要反复切换材料。

学生需要一个能持续整理课程资料的个人学习工具：既能看到知识的组织与联系，又能围绕自己的问题阅读有依据的解释。新增资料后，课程知识应得到补充，学生已经编辑的笔记和原有引用仍应保留。

本项目面向比赛，交付目标是在本机浏览器中可运行、以真实教材驱动的 Demo，重点支持日常课后学习。当前项目只有已确认的方案文档，尚无应用实现、依赖配置或现成测试。

## Solution

学生为每门课程建立课程学习空间，导入 Markdown 学习资料并选择整理范围。系统通过固定的知识整理流程，生成可追溯的知识点页面与知识图谱；学生可以浏览章节、查看关联、打开原文依据、进行课程问答、保存个人笔记，并围绕目标获取学习路线。

知识图谱以章节和知识点为节点，展示包含、前置和对比关系。回答默认依据当前课程资料，资料不足时明确说明；学生主动选择的拓展解释始终标为模型补充。学习路线依据知识之间的前置关系，不声称诊断了学生的掌握程度。

追加资料或提交问题反馈后，系统构建候选知识版本，在校验成功后一起发布图谱、页面和来源。整理期间旧知识仍可使用，失败可重试，个人笔记独立保留。学生可以导出课程资料包，在应用之外阅读知识页面、关系索引、笔记及原始 Markdown。

采用 LLM Wiki 持续整理和关联知识的思想，不绑定某个现成 LLM Wiki 项目。全部模型调用统一使用 DeepSeek API 的 `deepseek-flash`。

## User Stories

1. 作为学生，我希望独立建立课程学习空间，以便无需等待教师参与就能整理自己的课程资料。
2. 作为学生，我希望在本机管理多门课程，以便分别保存各门课程的资料、知识和笔记。
3. 作为学生，我希望直接通过本机浏览器使用工具，以便无需注册账号即可开始学习。
4. 作为学生，我希望向一门课程导入多份 Markdown 学习资料，以便把教材和补充材料放到同一学习范围中。
5. 作为学生，我希望选择需要整理的章节或资料范围，以便先处理当前正在学习的内容。
6. 作为学生，我希望区分已导入和已整理的内容，以便知道哪些材料已形成可用课程知识。
7. 作为学生，我希望查看知识整理任务的进度、失败原因和重试入口，以便理解当前处理状态并继续未完成的工作。
8. 作为学生，我希望导入后保留原始资料和章节出处，以便随时核对系统的解释。
9. 作为学生，我希望章节编号在标题层级混乱的教材中仍能用于组织内容，以便按教材结构浏览。
10. 作为学生，我希望能阅读文字、公式和代码，并看到缺失图片提示，以便理解材料内容及其缺失部分。
11. 作为学生，我希望先看到课程的章节概览，再展开章节中的知识点，以便逐步理解知识结构。
12. 作为学生，我希望区分包含、前置和对比关系，以便知道知识点之间具体是什么联系。
13. 作为学生，我希望查看跨章节关联并按需打开全图，以便发现分散在教材不同位置的相关知识。
14. 作为学生，我希望点击知识点后阅读其说明及相关概念，以便把图谱中的节点转化为可理解的内容。
15. 作为学生，我希望从知识点页面打开对应原文章节或段落，以便检查知识说明的依据。
16. 作为学生，我希望查看详情、原文和问答后保留图谱浏览位置，以便继续原来的探索。
17. 作为学生，我希望能区分关系的资料依据与模型推断，以便判断学习建议的可靠程度。
18. 作为学生，我希望围绕当前课程全部资料提问，以便获得综合相关知识的回答。
19. 作为学生，我希望把问答范围限制到指定资料或章节，以便围绕当前学习内容讨论。
20. 作为学生，我希望选中的知识点成为提问焦点，同时仍能引用允许范围内的相关概念，以便提出对比或跨知识点问题。
21. 作为学生，我希望清楚看到当前课程与问答范围，并在切换课程时同步范围，以便避免混用其他课程的资料。
22. 作为学生，我希望使用简称、别名、两字术语或不够精确的表述也能查找知识，以便用自然的方式提问。
23. 作为学生，我希望回答中的关键结论带有可打开的原文依据，以便核对答案是否受到资料支持。
24. 作为学生，我希望资料不足或问题依赖缺失图片时得到明确说明，以便知道何时需要补充材料。
25. 作为学生，我希望检索没有找到内容时，系统不要直接断言教材中不存在该内容，以便正确理解回答的限制。
26. 作为学生，我希望逐步看到生成的回答，并知道回答是否完成或中断，以便不把未完成内容当作最终答案。
27. 作为学生，我希望主动选择拓展解释，并能辨认其中的模型补充，以便在需要时了解资料之外的内容。
28. 作为学生，我希望拓展解释不会自动写入课程知识库，以便保留课程资料与模型补充之间的区别。
29. 作为学生，我希望基于选定知识点、解释或问答生成个人笔记，以便保存自己的学习成果。
30. 作为学生，我希望编辑并保存笔记正文，以便加入自己的理解和补充说明。
31. 作为学生，我希望知识库更新时保留我对笔记的修改，以便持续积累个人成果。
32. 作为学生，我希望笔记保留原有引用，相关依据变化时提示检查，以便自行决定是否更新笔记。
33. 作为学生，我希望笔记及其导出结果保留拓展解释标记，以便以后仍能辨认模型补充。
34. 作为学生，我希望根据学习目标和当前学习位置查看建议路线，以便知道可以先理解哪些知识。
35. 作为学生，我希望路线在图谱中突出显示并解释安排理由，以便理解学习顺序及其依据。
36. 作为学生，我希望路线中的循环、缺口和待核对关系明确显示，以便不把不完整建议当作完整路线。
37. 作为学生，我希望学习路线不声称知道我的掌握程度，以便正确使用基于知识结构的建议。
38. 作为学生，我希望向已有课程追加 Markdown，以便持续补充课程知识。
39. 作为学生，我希望不同资料对同一概念的说明能够整合并保留出处，以便减少重复阅读。
40. 作为学生，我希望同名但含义不同的概念保持区分，无法判断的概念标记待核对，以便避免错误合并。
41. 作为学生，我希望概念改名、增加别名或出现在其他章节时仍保留原有身份，以便已有关系和引用继续可用。
42. 作为学生，我希望不同资料中的冲突表述及适用语境同时保留，以便对照来源进行判断。
43. 作为学生，我希望资料整理期间继续浏览已有知识、提问和保存笔记，以便不中断当前学习。
44. 作为学生，我希望更新成功后图谱、页面和来源一起切换，并能看到变化摘要，以便理解新增、补充和冲突内容。
45. 作为学生，我希望更新失败时保留原有知识和笔记，并可重试任务，以便不因生成故障丢失已有成果。
46. 作为学生，我希望首次整理失败时看到真实状态，以便不误以为已经拥有可用知识库。
47. 作为学生，我希望程序中断后能够继续未完成的任务，以便复用已保存的成功处理结果。
48. 作为学生，我希望知识更新后旧回答和旧笔记仍能打开当时的原文，以便核查历史学习内容。
49. 作为学生，我希望针对知识点或关系提交问题反馈，以便要求系统回查资料并重新整理相关内容。
50. 作为学生，我希望尚未解决的问题保持明确状态，以便不把任务执行完成误认为内容已经修正。
51. 作为学生，我希望导出当前课程的知识页面、关系索引、个人笔记和已导入原始 Markdown，以便在应用之外保存和阅读。
52. 作为学生，我希望导出包中的页面链接、来源引用和历史笔记依据仍然可用，以便独立核查内容。
53. 作为学生，我希望关闭并重新启动工具后仍能读取课程数据，以便继续之前的学习。
54. 作为比赛演示者，我希望完成首次准备后用一条命令启动应用，以便通过一个本机地址演示。
55. 作为比赛演示者，我希望基础知识库来自真实教材和真实模型流程，并可重新构建，以便展示可复现的实际能力。
56. 作为比赛演示者，我希望现场加入一小段保留真实出处的材料并观察知识变化，以便展示持续整理的能力。
57. 作为比赛演示者，我希望用代表性教材问题核对答案要点和依据，以便知道 Demo 的实际表现与限制。

## Implementation Decisions

1. **运行形态。** 同一项目实现本机单人、多课程 Web 应用，无登录注册。服务只面向本机访问，前端和业务接口通过同一个本机地址提供；运行时模型调用需要联网。
2. **已选技术。** React、TypeScript、Vite 构建前端，Cytoscape.js 展示知识图谱，Python 和 FastAPI 实现后端，本机工作进程执行知识整理任务，SQLite 保存应用状态。前端类型检查与构建分别执行；具体依赖版本在实施时验证并锁定。
3. **模块职责。** 划分资料、知识、整理任务、学习、个人笔记、导出六个模块。模块拥有自己的业务数据，调用方通过业务接口协作，不直接修改其他模块的数据。它们共同支撑用户操作，不拆分为独立服务。

| 模块 | 主要职责 | 对外业务接口 |
| --- | --- | --- |
| 资料 | 保留原文，识别章节，生成可定位的原文片段 | 导入资料、读取章节与原文片段 |
| 知识 | 管理知识点身份、关系、页面和知识版本 | 读取指定版本、校验并发布候选版本 |
| 整理任务 | 执行固定处理流程，保存任务状态和步骤结果 | 发起整理或纠错、查询进度、重试失败任务 |
| 学习 | 按范围检索，生成带依据回答，计算并解释学习路线 | 提问、请求学习路线 |
| 个人笔记 | 生成、编辑和保存笔记，保留引用及依据变化提示 | 生成笔记、保存修改、读取笔记 |
| 导出 | 汇集知识、笔记及原文，生成可独立阅读的课程资料包 | 导出当前课程 |

4. **持久化与权威状态。** SQLite 保存课程、资料元信息、原文片段定位、稳定知识点身份与别名、知识版本、版本内关系和页面、个人笔记、任务与步骤结果。知识点页面和笔记正文以 Markdown 保存，原始资料文件独立保留。SQLite 是应用知识状态的权威来源，教材原文是核查事实依据的来源；图谱、页面、问答和导出不各自维护一份可独立变化的知识。
5. **导入与整理范围。** 第一版接收 Markdown，导入范围与整理范围分别记录。依据章节编号处理现有教材的标题层级混乱；展示规范化不能破坏到原文的映射。没有整理的章节不能显示为已整理。保留原始文本，显示缺失图片，不承诺自动修复全部 OCR 残留或公式错误。
6. **原文片段与引用。** 程序分配稳定的原文片段标识，并维护资料、章节、段落和原文位置。模型只能选择本次提供的标识，不能自行编造页码或行号。程序校验引用标识、引用文本与允许范围；引用存在不代表其一定支持回答结论，语义支持另行验收。
7. **图谱模型。** 节点只有章节和知识点，关系只有包含、前置和对比。知识点可以属于多个章节；公式与例题作为页面内容，不成为独立节点。前置关系具有方向，不能仅按教材出现顺序生成；资料依据与模型推断需要区分。
8. **图谱交互。** 默认章节概览，支持展开章节、查看跨章节关联和全图。打开知识点页面、原文依据或问答时保留图谱浏览位置。页面支持文字、公式及代码阅读，学习路线可在图谱中突出显示。
9. **知识整理流程。** 程序固定执行资料与章节识别、原文片段建立、知识点和关系抽取、概念整合与冲突处理、页面生成、校验、发布。学习资料是参考内容，不能改变程序规则或授权模型任意操作文件。失败能定位到处理步骤，相关步骤可重试。
10. **统一模型适配器。** 所有模型调用集中经由一个 DeepSeek 适配器，统一使用 `deepseek-flash`，包括抽取、整合、目录选择、问答、笔记生成和路线解释。后端采用 `/responses`；抽取与整合开启思考并使用 JSON Schema 输出，交互问答默认关闭思考并流式返回。思考模式和请求参数可以依据样本调整，不把 Pro 设为默认、对照要求或自动回退模型。调用凭据仅由后端持有。
11. **模型响应处理。** 适配器区分空输出、截断、请求错误、可重试错误与正常完成。结构合法不等于内容正确；输出仍需通过业务、来源和发布校验。应用维护自己的上下文、会话所需状态和后台任务，不依赖模型平台替应用保存。
12. **稳定概念身份。** 知识点在课程内拥有稳定标识，名称和别名可以变化。追加资料按定义、上下文和依据判断概念是否相同；同义表达可以整合，同名异义不能强行合并。无法确认的候选保留独立身份并标记待核对。冲突说明保留不同来源及适用语境，不把普通措辞差异都认定为冲突。
13. **候选版本与发布。** 每次整理先形成候选知识版本，通过结构、关系端点、来源和页面一致性校验后，才切换当前知识版本。发布一起更新图谱、页面和来源，展示新增、补充及冲突摘要。更新失败保留原有已发布版本；首次失败不产生虚假的可用知识状态。
14. **版本读取与历史引用。** 关联的图谱、详情与一次问答读取同一知识版本；新版本不能悄悄改变正在使用的引用含义。旧回答、笔记及其来源定位保留相应版本与当时原文。后台整理和新版本发布不覆盖个人笔记，包括整理期间保存的个人修改。
15. **持久任务与恢复。** 本机工作进程配合 SQLite 保存任务、阶段状态、成功结果和失败原因，一次只执行一个知识整理任务。中断后复用已保存的成功结果，对可重试错误有限重试，其余错误明确显示。未持久保存结果的外部请求可能被再次执行，不承诺模型请求恰好执行一次；同一任务恢复或重试不能重复发布知识。
16. **检索路线。** 使用概念目录、别名、中文关键词和图谱关联定位知识，再回查支持回答的原文。含糊问题可由 Flash 从允许的课程概念目录选择候选，程序验证标识及范围。必须处理“进程”“线程”等短词，不依赖不适合中文短词的检索默认行为。暂不引入向量检索；只有代表问题暴露明显召回不足时，再依据失败案例补充。
17. **问答范围。** 默认允许使用当前课程的资料，用户可限制资料或章节。选中的知识点是提问焦点，不自动把问答范围缩成单个知识点。界面明确显示课程与范围，切换课程同步调整范围；模型选择与原文检索不能越过允许范围。未命中检索结果只能说明当前未找到依据，不能证明教材中不存在该知识。
18. **回答与拓展解释。** 默认回答的关键结论需要资料依据；证据不足或缺失图片导致无法判断时明确说明。流式内容的生成中、完成和中断状态分开呈现，最终引用校验未通过不能视为完成答案。资料外解释由用户主动启用，标为模型补充，不自动进入课程知识库；保存为笔记和导出后仍保留标记。
19. **个人笔记。** 知识点页面自动维护，个人笔记独立生成、编辑与保存。笔记保留所依据的知识版本、原文引用及拓展标记；相关依据变化时提示学生自行检查，不自动改写个人正文。问题反馈及重新生成页面同样不能覆盖笔记。
20. **学习路线。** 程序围绕目标知识点收集所需前置知识并排序，结合当前学习位置展示路线，由模型解释安排理由。只把前置关系用于排序，包含和对比关系不参与前置顺序计算。检测目标相关范围的循环、缺口和待核对关系，展示可确定部分及限制，不把部分路线描述为完整路线，不宣称了解学生的掌握程度。
21. **问题反馈。** 用户可对知识点或关系说明问题，系统回查原文并重新整理相关范围。用户反馈不直接变成教材事实；任务完成与问题是否解决分别表达，不能仅凭执行完成声称已经修正。
22. **导出。** 导出当前课程采用的已发布知识版本，并固定本次导出所采用的笔记和原文内容，生成知识页面、关系索引、个人笔记与已导入原始 Markdown。保留可用相对链接、来源定位及拓展标记，收齐历史笔记引用需要的依据。应用外修改导出文件不自动同步回课程知识；原本缺失的图片明确标记，不承诺恢复。
23. **业务契约。** 整理与纠错操作返回可查询的任务身份和状态；知识读取可指定课程及知识版本；提问携带问答范围、可选焦点和拓展选择，返回有完成状态的回答及引用；笔记操作保留正文、引用及版本关联；导出返回选定内容的可独立阅读资料包。具体 HTTP 路由、请求字段名称和数据库表名由实现确定，必须满足这些业务语义。
24. **本机交付。** 提供初次依赖准备与前端构建说明，完成准备后一条命令启动后端和工作进程，后端提供构建后的前端。持久数据置于独立的本地数据目录；重启后可继续读取课程数据。交付项目与启动脚本，不要求桌面安装包或公网部署。
25. **实现顺序。** M1 用一小节真实教材贯通模型接入、整理、持久化、图谱和来源；M2 完成问答、笔记和路线；M3 完成增量、反馈、版本一致性及恢复；M4 完成导出、样本验收、可复现演示和本机交付。不能用静态图谱或仅安装成功代替 M1 的真实处理结果。

## Testing Decisions

测试沿用已经确认的业务接口和用户可观察结果。优先从发起整理、读取知识、提问、保存笔记、请求路线和导出等对外操作验证完整行为；必要时直接测试相关模块公开接口，不为每个内部函数新增测试接口。外部模型调用使用统一适配器作为可控替换边界，真实 SQLite、资料保存和模块协作尽量参与验证。

好测试验证学生实际得到什么、哪些稳定约束必须成立，不绑定内部调用顺序、私有函数、临时表结构或自然语言逐字输出。知识整理的可控响应仅用于复现边界和故障，不能作为真实模型演示的内容。

1. **现有基础。** 当前项目只有设计文档，没有已有应用接口或可复用测试套件。测试依据是已确认的产品验收标准、六个模块的公开业务接口和四个里程碑的完成标准，不虚构现成测试先例。
2. **资料与来源。** 通过导入和原文读取验证原文保留、章节识别、整理范围、稳定片段定位及缺失图片提示。标题规范化后，引用仍应落到真实原文；未整理内容不能显示为已整理。
3. **知识与概念整合。** 通过整理后读取知识验证同义概念整合、同名异义区分、跨章节关联、名称变化后的稳定身份、待核对候选与冲突出处。检查关系类型和方向，不以模型生成的节点数量作为成功标准。
4. **任务与发布。** 使用可控模型响应复现空输出、截断、非法片段标识、无效关系端点、可重试及不可重试失败。观察任务状态和已发布知识，确认错误候选不发布、首次失败不显示可用知识、已有版本仍可读取，成功发布后各视图一致。
5. **恢复。** 在可复现的处理阶段中断并重新启动工作进程，经任务和知识读取检查保存结果可复用、任务能继续、不会重复发布。验证外部调用结果未保存时的重试行为，不把“模型只调用一次”设为必须成立的条件。
6. **学习与范围。** 通过提问和引用读取验证课程隔离、资料和章节限制、焦点不错误缩小范围、同一回答固定知识版本。覆盖两字术语、别名及含糊表达；检索未命中不能被包装成确定的资料不存在。
7. **真实模型内容验收。** 准备约 20 个真实教材问题，为每题记录可接受要点、原文支持位置或资料不足的原因，覆盖概念解释、同义和模糊表达、跨知识点问题及资料不足。使用真实 Flash 回答后人工对照教材核查结论与引用，不以另一模型作为唯一裁判，不要求答案逐字一致。引用存在和引用支持结论分别检查。
8. **流式回答与拓展。** 验证生成中、完成、中断及引用校验失败的可见区别。拓展内容必须主动启用且不进入课程知识，保存笔记及导出后标记仍可见。
9. **学习路线。** 通过路线接口验证目标前置知识、排序与关系类型，包含和对比关系不能冒充前置关系。为循环、缺口、待核对关系及部分可确定路线构造样例，检查限制是否正确呈现。
10. **个人笔记与历史引用。** 经笔记操作验证生成、编辑、保存和重新读取。追加资料、反馈纠错、发布新版本及整理期间保存笔记后，个人修改不被覆盖；相关依据变化有提示，旧回答和笔记仍能打开当时的原文。
11. **导出。** 从导出操作获得资料包并在应用之外读取，核对四类内容、所采用的知识版本、笔记正文、相对链接、历史来源及拓展标记。既有缺图作为明确缺失状态检查，不能把应存在的知识页面或来源链接失效当成正常缺图。
12. **浏览器主流程。** 用实际界面检查课程与范围切换、章节展开、跨章节关联、详情与原文、图谱位置保留、提问、笔记和路线突出显示。浏览器检查补充业务接口无法证明的交互，不为同一业务规则在每一层重复构造测试。
13. **交付检查。** 独立运行前端类型检查和构建，验证后端与工作进程启动、静态界面加载、数据持久化及重启。在目标演示电脑按说明走完真实预构建、现场增量和导出流程，记录实际耗时及已知限制，不预设未经测量的准确率、节点数量或响应时间。

| 里程碑 | 可观察的通过条件 |
| --- | --- |
| M1 真实资料到图谱 | 一小节真实 Markdown 经真实模型处理得到可浏览图谱与知识页面，引用可核查，重开后数据仍在，未整理范围不显示完成 |
| M2 学习使用 | 真实课程中能进行有依据的问答、生成并编辑笔记、获取有顺序且标明依据或限制的学习路线 |
| M3 持续更新与恢复 | 追加资料真实改变知识，反馈可回查，失败及中断不破坏既有知识和笔记，恢复后发布一致，历史引用仍可核查 |
| M4 演示交付 | 目标电脑上按说明启动并完成主流程，预构建可复现，增量有真实出处，约 20 个代表问题完成核对，导出资料包可独立阅读 |

## Out of Scope

- PDF、扫描 PDF、OCR 输入，图片理解，以及自动找回缺失图片。
- 对现有教材的全部识别残留、公式错误或排版问题进行完美自动修复。
- 将例题和公式作为独立图谱节点，自由绘制或任意编辑整张图谱。
- 依赖教师参与的流程、班级共享、多人协作、账号权限、公网服务和生产规模部署。
- 短测诊断、自动判断掌握度、长期复习调度和完整教学管理系统。
- 自动同步用户在应用外对导出 Markdown 的修改。
- 由自主 Agent 任意决定文件读写、跳过校验或直接修改已发布知识。
- 第一版预先引入独立向量数据库；是否补充向量检索由实际召回问题驱动。
- 混用其他模型、默认 Pro 回退或以 Pro 对照作为验收前提。
- 桌面安装包、离线模型推理，以及对外部模型请求恰好执行一次的保证。
- 声称整本教材已经整理，或承诺未经验证的处理时长、知识点数量和准确率。

## Further Notes

本规格汇总已确认的产品与技术决策；生成规格和发布 issue 均不表示开始应用实现，也不表示已经通过验收。

首本演示教材为汤小丹等编著的《计算机操作系统（第四版）》。演示总体范围为第 2 章“进程的描述与控制”和第 3 章的 3.5—3.8 节。准备样本时从这一范围留出一小段用于现场增量，预构建使用其余选定内容；演示结束覆盖约定范围。教材摘录保留真实出处，不能伪称为教师新发的材料。教材正文和图片不随当前方案仓库发布。

主演示依次展示课程与整理范围、进程或线程的知识图谱和原文、进程与线程对比问答、可编辑笔记、理解死锁的学习路线、短资料追加、更新后的知识与保留的笔记、课程资料包导出。反馈纠错、资料不足和失败恢复另设短案例验证。

Flash 是用户明确指定的统一模型选择，依据是其对新版模型能力的判断，不是预算限制；项目尚未实测模型效果。此前仅查阅官方接口文档，实际兼容性、参数与表现需要在实施时验证。比赛尚无额外要求或确定排期，不新增费用上限或性能承诺。

发布到项目 issue tracker 时使用 `ready-for-agent` 标签，无需额外分诊。规格对应完整 Demo 范围，实现沿用四个里程碑及已有 25 项任务拆分。
